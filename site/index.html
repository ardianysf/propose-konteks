Four rooms, one job: telling a machine what to do.

One house, one line of instructions running through it: pen and paper, a tape, a programming language, and now a team that talks in plain words. Pick a room, or let the tour play.

1843 · Pen and paper

Ada Lovelace writes the first program.

For Charles Babbage’s Analytical Engine, a machine that was never built. Her Note G sets out, step by step, how it would compute Bernoulli numbers.

1936 · A tape

Alan Turing turns computing into an idea.

A tape, a head that reads and writes, and a table of rules. Turing showed this one simple machine can carry out any calculation that can be written as steps.

1969 to 1972 · A language

Unix and C make software a team sport.

At Bell Labs, from 1969 to 1972: an operating system and a language people could read and share. Code starts to outlive its authors, and teams build it together.

Today · A team and its agents

People decide, and agents build in the background.

The team explores on the board and settles on one decision. The agents take it from there: the screen writes the change, runs the checks and shows the result.

Each step moved the work closer to how people already talk.

Programming is theory building.

Agents write most of the code now. People still hold the theory: what the software is for, why it works the way it does, and what it should never do.

“Programming properly should be regarded as an activity by which the programmers form or achieve a certain kind of insight, a theory, of the matters at hand.”

Peter Naur, Programming as Theory Building, 1985

  1. Lead the vision.

    Decide what should exist, and what should not.

  2. Set the constraints.

    The budget ceiling, who may touch what, and what done means.

  3. Say yes.

    And own the decision.

  4. Judge the evidence.

    Read the plan, the test results, and the receipt. Know when they are thin.

  5. Hold the context.

    The things nobody wrote down.
