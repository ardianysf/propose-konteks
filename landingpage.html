“Programming properly should be regarded as an activity by which programmers form a theory of the matters at hand.”

Peter Naur · Programming as Theory Building, 1985

People hold the theory.

  • ↳Lead the visionDecide what should exist—and what should not.
  • ↳Set the constraintsName the budget, authority, and definition of done.
  • ↳Say yesApprove the plan and remain accountable for the outcome.
  • ↳Judge the evidenceKnow when the proof is strong enough to accept.
  • ↳Hold the contextCarry the things nobody wrote down.

Agents move the work.

  • ↳WriteTurn a human signal into a durable note.
  • ↳PlanRead the note and code, then return scope and a ceiling.
  • ↳BuildWork in isolation, across every affected repository.
  • ↳CheckClick through the real work and keep the screenshots and receipt.
  • ↳WatchStay awake for logs, alerts, and changes that need a response.

No agent has more authority than the people around it. Every decision that matters comes back to a person.

How It Works

Initiatives, issues, releases. A person can steer at every step.

Each one moves through the same six signals—a note, a comment, a reaction, a reply, a confirmation, an acceptance. You steer with them. The agents plan, build, and check inside the limits you set, and every step lands in the record.

Note.

You can step in here.

Every workflow has a human stop. React to a note, approve a plan, decide to ship, or inspect the record without hunting through agent transcripts.

Note → plan → accept

Initiative

  1. Write the intent as a note; teammates add comments and reactions.
  2. A plan comes back with a quoted ceiling, set before any work runs.
  3. You say yes to the scope, the cost, and the evidence it must return.
  4. Accept the tested pull requests—the receipt lands in the record with them.
Human stop · approve the plan
Alert → contain → resolve

Issue

  1. An agent catches the alert, reads the severity, and opens the issue.
  2. It contains the incident and proposes a fix on an isolated branch.
  3. The fix waits for your approval before the normal build begins.
  4. You authorize it, and the timeline from alert to resolution writes itself.
Human stop · authorize the fix
Accepted → gather → ship

Release

  1. Accepted work gathers itself into a release, nothing hand-carried.
  2. A person still decides the moment it ships.
  3. The release reads like a post the whole team can react to.
  4. Ship it, and the record keeps who chose to, and what went out.
Human stop · decide to ship
Participate → return → compare

Leaderboard

  1. People appear by participation—by what they were actually part of.
  2. Models appear by what they returned for what they cost.
  3. Only counts you can defend make it onto the board.
  4. Never a manufactured productivity score.

Authority

  • Least-privilege roles and groups
  • Access scoped to exact Systems

Money

Every piece of work is quoted before it runs.

  • Your yes locks the ceiling
  • Quotes calibrated from delivery history
  • Automation shadows real work first
  • Provider bill shown separately, never marked up

Evidence

  • Real decisions return to a person
